# 可选组件启用矩阵

## 1. 总览

本项目 **没有使用任何 `@ConditionalOnProperty`、`@ConditionalOnBean` 等 Spring 条件注解**，也没有 Maven Profile。所有组件的开关都是通过 **注释/取消注释 Java 注解** 实现的，带有 `// todo` 标记。

| 组件 | 当前状态 | 开关方式 | pom 依赖 |
|------|---------|---------|---------|
| Redis | **已启用** | MainApplication exclude 切换 | `spring-boot-starter-data-redis` |
| Redisson | **已启用** | `@Configuration` 已生效 | `redisson 3.21.0` |
| Spring Session Redis | 部分启用 | `application.yml` 中 `store-type` 未设为 redis | `spring-session-data-redis` |
| Elasticsearch | **配置存在，@Document 已注释** | 取消注释 `@Document` | `spring-boot-starter-data-elasticsearch` |
| ES 同步 Job（4 个） | **已注释** | 取消注释 `@Component` | 同上 |
| HotKey | **已注释** | 取消注释 `@Configuration` | `hotkey-client 0.0.4-SNAPSHOT`（system scope） |
| Nacos | **已注释** | 取消注释 `@Component` | `nacos-config-spring-boot-starter 0.2.12` |
| Sentinel | **已启用** | 注释 `@Component` 可关闭 | `spring-cloud-starter-alibaba-sentinel 2021.0.5.0` |
| AuthInterceptor (AOP) | **已注释**（被 Sa-Token 替代） | 取消注释 `@Aspect` + `@Component` | 无额外依赖 |

## 2. 各组件详细分析

### 2.1 Redis

**当前状态**：已启用

`MainApplication.java` 中的切换逻辑：

```java
// todo 如需开启 Redis，须移除 exclude 中的内容
// @SpringBootApplication(exclude = {RedisAutoConfiguration.class})
@SpringBootApplication
```

当前 `@SpringBootApplication` 没有 exclude，`RedisAutoConfiguration` 生效。`application.yml` 配置：

```yaml
spring:
  redis:
    database: 1
    host: localhost
    port: 6379
    timeout: 5000
```

**运行时依赖**：需要 Redis 服务在 `localhost:6379` 可达。如果 Redis 不可用，应用启动时 `RedissonConfig` 创建 `RedissonClient` Bean 不会立即失败（延迟连接），但实际使用 Redis 的操作（如缓存、分布式锁）会抛运行时异常。

**如果要关闭 Redis**：将注释切换到 exclude 行：

```java
@SpringBootApplication(exclude = {RedisAutoConfiguration.class})
// @SpringBootApplication
```

同时需要注释 `RedissonConfig` 的 `@Configuration`，否则 `RedissonClient` Bean 创建会因缺少 Redis 配置而失败。

### 2.2 Redisson

**当前状态**：已启用

```java
// config/RedissonConfig.java
@Configuration
@ConfigurationProperties(prefix = "spring.redis")
public class RedissonConfig {
    @Bean
    public RedissonClient redissonClient() {
        Config config = new Config();
        config.useSingleServer()
                .setAddress("redis://" + host + ":" + port)
                .setDatabase(database)
                .setPassword(password);
        return Redisson.create(config);
    }
}
```

- 读取 `spring.redis.*` 配置
- 创建单机模式 `RedissonClient`
- 用于分布式锁（`RedissonClient.getLock()`）等场景

**关闭方式**：注释 `@Configuration`，并确保没有代码调用 `redissonClient` Bean。

### 2.4 Elasticsearch

**当前状态**：连接配置存在，但核心注解被注释

**`QuestionEsDTO.java`**：

```java
// todo 取消注释开启 ES（须先配置 ES）
//@Document(indexName = "question")
@Data
public class QuestionEsDTO implements Serializable { ... }
```

`PostEsDTO` 同样 `@Document` 被注释。

**`application.yml` 配置**：

```yaml
spring:
  elasticsearch:
    uris: http://localhost:9200
    username: root
    password: 123456
```

**运行时行为**（`@Document` 注释状态）：
- `QuestionEsDao`（`ElasticsearchRepository<QuestionEsDTO, Long>`）的 Bean 可能被 Spring Data 创建（通过泛型推断），但由于 `@Document` 缺失，实际调用 `save()`/`deleteById()`/`search()` 会抛异常
- `QuestionServiceImpl` 中的 `syncQuestionToEs()`、`cleanupAfterQuestionDelete()`、`batchDeleteQuestions()` 都有 try/catch，失败仅 warn
- `searchFromEs()` 失败后，Controller 层 catch 并降级到 MySQL 查询
- **结论：ES 不启用时应用可正常运行，仅日志中有 warn**

**启用步骤**（需按顺序）：

1. 确保 Elasticsearch 服务可达
2. 取消 `QuestionEsDTO` 的 `@Document(indexName = "question")` 注释
3. 取消 `PostEsDTO` 的 `@Document(indexName = "post")` 注释
4. 取消 `FullSyncQuestionToEs` 和 `FullSyncPostToEs` 的 `@Component` 注释
5. 重启应用（全量同步执行一次）
6. 全量同步完成后可注释回 FullSync Job（避免每次启动重复执行）
7. 取消 `IncSyncQuestionToEs` 和 `IncSyncPostToEs` 的 `@Component` 注释（增量补偿）

### 2.5 ES 同步 Job（4 个类）

| 类 | 包路径 | 类型 | 当前状态 |
|----|--------|------|---------|
| `FullSyncQuestionToEs` | `job/once/` | `CommandLineRunner`（启动时执行一次） | `//@Component` |
| `FullSyncPostToEs` | `job/once/` | `CommandLineRunner` | `//@Component` |
| `IncSyncQuestionToEs` | `job/cycle/` | `@Scheduled(fixedRate=60000)` | `//@Component` |
| `IncSyncPostToEs` | `job/cycle/` | `@Scheduled(fixedRate=60000)` | `//@Component` |

**注意**：`MainApplication` 上 `@EnableScheduling` 已生效，所以只要 IncSync Job 的 `@Component` 被取消注释，`@Scheduled` 就会自动生效。

**FullSync Job 的特殊性**：
- 实现 `CommandLineRunner`，在 Spring 容器启动完成后立即执行
- 拉取全量数据（含软删记录），每 500 条批量写入 ES
- 如果 ES 不可用，`saveAll()` 抛异常，会导致 **应用启动失败**（`CommandLineRunner.run()` 中的异常会阻止启动完成）
- 所以 FullSync Job 只在确认 ES 可用时才应取消注释

### 2.7 Nacos

**当前状态**：已注释关闭

**涉及类**：

| 类 | 注释内容 |
|----|---------|
| `blackfilter/NacosListener.java` | `//@Component` |

```java
@Slf4j
// todo 取消注释开启 Nacos（须先配置 Nacos）
//@Component
public class NacosListener implements InitializingBean {
    @NacosInjected
    private ConfigService configService;

    @Override
    public void afterPropertiesSet() throws Exception {
        String config = configService.getConfigAndSignListener(
                dataId, group, 3000L, new Listener() {
            @Override
            public void receiveConfigInfo(String configInfo) {
                BlackIpUtils.rebuildBlackIp(configInfo);
            }
        });
        BlackIpUtils.rebuildBlackIp(config);
    }
}
```

**`application.yml` 配置**：

```yaml
nacos:
  config:
    server-addr: 127.0.0.1:8848
    bootstrap:
      enable: true
    data-id: mianshiya
    group: DEFAULT_GROUP
    type: yaml
    auto-refresh: true
```

**功能说明**：
- Nacos 在此项目中仅用于 **IP 黑名单的动态配置下发**
- 监听 Nacos 配置变更事件，收到新配置后调用 `BlackIpUtils.rebuildBlackIp()` 重建 Bloom Filter
- 与 `BlackIpFilter`（`@WebFilter`，拦截所有请求 `/*`）配合工作

**当前 BlackIpFilter 的状态**：
- `BlackIpFilter` **本身是启用的**（`@WebFilter` + `MainApplication` 上的 `@ServletComponentScan`）
- 但由于 `NacosListener` 被注释，`BlackIpUtils` 中的黑名单始终为空
- 效果：Filter 会对每个请求执行 IP 检查，但因为黑名单为空，所有请求都会通过

**启用步骤**：
1. 确保 Nacos 服务在 `127.0.0.1:8848` 可达
2. 取消 `NacosListener` 的 `@Component` 注释
3. 在 Nacos 控制台中创建 `dataId=mianshiya`、`group=DEFAULT_GROUP` 的配置项，内容为 IP 黑名单

**pom 依赖**：`nacos-config-spring-boot-starter 0.2.12`（已在 pom.xml 中引入）

### 2.8 Sentinel

**当前状态**：已启用

**涉及类**：

| 类 | 状态 |
|----|------|
| `sentinel/SentinelRulesManager.java` | `@Component`（已生效） |

```java
@Component
public class SentinelRulesManager {
    @PostConstruct
    public void initRules() throws Exception {
        initFlowRules();    // 参数限流规则
        initDegradeRules(); // 熔断降级规则
        listenRules();      // 文件持久化监听
    }
}
```

**已配置的规则**：

| 规则类型 | 资源 | 参数 |
|---------|------|------|
| ParamFlowRule | `listQuestionVOByPage` | paramIdx=0（IP），60 次/60 秒 |
| DegradeRule（慢调用比例） | `listQuestionVOByPage` | >20% 慢调用（阈值 3s），窗口 60s，最小请求数 10 |
| DegradeRule（异常比例） | `listQuestionVOByPage` | >10% 错误率，窗口 60s，最小请求数 10 |

**规则持久化**：写入项目根目录下 `sentinel/FlowRule.json` 和 `sentinel/DegradeRule.json`，使用 `FileRefreshableDataSource` + `FileWritableDataSource` 双向同步。

**Controller 中的使用**：

| 接口 | 方式 |
|------|------|
| `QuestionController.listQuestionVOByPageSentinel()` | 手动 `SphU.entry()` API，捕获 `BlockException` 和 `DegradeException` |
| `QuestionBankController.listQuestionBankVOByPage()` | `@SentinelResource` 注解，配 `blockHandler` 和 `fallback` |

**如果要关闭 Sentinel**：注释 `SentinelRulesManager` 的 `@Component`。注意 Controller 中使用 Sentinel 的代码不会被影响 — `SphU.entry()` 在没有规则时直接通过，`@SentinelResource` 注解在没有 Sentinel 上下文时不起作用。但如果想完全移除 Sentinel，还需注释 pom 依赖。

## 3. 启用决策矩阵

下表汇总各组件启用时需要取消注释的位置和前置依赖：

| 组件 | 取消注释位置 | 前置条件 | 运行时影响 |
|------|------------|---------|-----------|
| Redis | 无需操作（已启用） | Redis 服务可达 | 缓存、分布式锁可用 |
| 关闭 Redis | `MainApplication` 切换到 exclude 行 + 注释 `RedissonConfig` | 无 Redis 服务 | 所有 Redis 操作不可用 |
| 分布式 Session | `application.yml` → `store-type: redis` | Redis 已启用 | Session 跨实例共享 |
| ES 搜索 | `QuestionEsDTO` / `PostEsDTO` 的 `@Document` | ES 服务可达 | 全文搜索可用 |
| ES 全量同步 | `FullSync*ToEs` 的 `@Component` | ES 已启用 + ES 服务可达 | 启动时全量灌入（ES 不可用会导致启动失败） |
| ES 增量同步 | `IncSync*ToEs` 的 `@Component` | ES 已启用 | 每分钟补偿同步 |
| HotKey | `HotKeyConfig` 的 `@Configuration` + Controller 代码块 | Etcd 服务可达 + JAR 在 classpath | 热点 Key 本地缓存 |
| Nacos | `NacosListener` 的 `@Component` | Nacos 服务可达 | IP 黑名单动态下发 |
| 关闭 Sentinel | `SentinelRulesManager` 的 `@Component` 注释掉 | 无 | 限流/熔断失效 |

| `cos.client.accessKey` / `cos.client.secretKey` / `cos.client.region` / `cos.client.bucket` | 腾讯云 COS 存储 | `xxx` |
