# 可选组件启用矩阵

> 基于源码分析。本项目的 Redis、ES、HotKey、Nacos、Sentinel 五个可选组件处于不同的启用状态。本文档说明每个组件当前默认状态、启用所需操作、涉及的类以及运行时影响。

## 1. 总览矩阵

| 组件 | pom 依赖 | 配置类/注解 | YAML 配置 | 业务代码 | 默认状态 | 启动时必需 |
|------|----------|------------|-----------|---------|---------|-----------|
| **Redis + Redisson** | 活跃 | `@Configuration` 活跃 | 活跃 | 活跃 | **已启用** | **是** |
| **Spring Session Redis** | 活跃 | N/A | `store-type` 已注释 | N/A | **未启用** | 否 |
| **Elasticsearch** | 活跃 | `@Document` 已注释 | 活跃 | 活跃（带 try-catch） | **半启用** | 否 |
| **ES 同步 Job（4个）** | N/A | `@Component` 已注释 | N/A | N/A | **未启用** | 否 |
| **HotKey** | 活跃（system scope） | `@Configuration` 已注释 | 活跃但无效 | 使用代码已注释 | **未启用** | 否 |
| **Nacos** | 活跃 | `@Component` 已注释 | 活跃（bootstrap.enable: true） | N/A | **半启用** | 见下文 |
| **Sentinel** | 活跃 | `@Component` 活跃 | N/A | 活跃 | **已启用** | 否（纯本地库） |

## 2. Redis + Redisson

### 2.1 当前状态：已启用，启动时必须可用

Redis 是当前唯一一个**硬依赖**的外部组件。应用启动时会创建 Redisson 连接，如果 Redis 不可用，应用无法启动。

### 2.2 涉及的类

| 类 | 文件位置 | 注解状态 | 功能 |
|----|---------|---------|------|
| `RedissonConfig` | `config/RedissonConfig.java` | `@Configuration` **活跃** | 读取 `spring.redis` 配置创建 `RedissonClient` Bean |
| `CounterManager` | `manager/CounterManager.java` | `@Service` **活跃** | 基于 Redis Lua 脚本的时间桶计数器，用于反爬 |
| `UserServiceImpl` | `service/impl/UserServiceImpl.java` | 注入 `RedissonClient` | 用户签到（BitMap）：`addUserSignIn()`、`getUserSignInRecord()` |
| `RedisConstant` | `constant/RedisConstant.java` | 常量类 | 定义签到 key 模式 `user:signins:{year}:{userId}` |

### 2.3 YAML 配置

```yaml
# application.yml
spring:
  redis:
    database: 1
    host: localhost
    port: 6379
    timeout: 5000
    # password: 123456    # 开发环境无密码
```

### 2.4 运行时影响（Redis 不可用时）

| 影响范围 | 表现 |
|---------|------|
| 应用启动 | **失败**（`RedissonConfig` 创建 Bean 时连接失败） |
| 用户签到 | 功能不可用，接口报错 |
| 反爬检测 | `CounterManager` 异常，查看题目详情时报错 |
| 分布式 Session | 无影响（`store-type: redis` 已注释，使用内存 Session） |

### 2.5 如需完全关闭 Redis

需要同时操作：

1. **MainApplication.java 第 18 行**：取消注释 exclude 版本的注解
   ```java
   // 当前状态（活跃）：
   @SpringBootApplication

   // 改为：
   @SpringBootApplication(exclude = {RedisAutoConfiguration.class})
   ```

2. **RedissonConfig.java 第 14 行**：注释掉 `@Configuration`

3. 相关业务代码需要提供降级方案或注释：
   - `CounterManager`：注释 `@Service` 或提供无 Redis 实现
   - `UserServiceImpl` 中的签到方法：需要处理 `RedissonClient` 注入失败

## 3. Elasticsearch

### 3.1 当前状态：半启用

pom 依赖和 YAML 配置均为活跃状态，Spring Boot 会尝试创建 ES 客户端连接。但 `@Document` 注解已注释，不会自动管理索引 schema。写操作有 try-catch 保护，搜索有 MySQL 降级。

### 3.2 涉及的类

| 类 | 文件位置 | 注解状态 | 功能 |
|----|---------|---------|------|
| `QuestionEsDTO` | `model/dto/question/QuestionEsDTO.java` | `@Document` **已注释** | Question 的 ES 文档映射 |
| `PostEsDTO` | `model/dto/post/PostEsDTO.java` | `@Document` **已注释** | Post 的 ES 文档映射 |
| `QuestionEsDao` | `esdao/QuestionEsDao.java` | 无特殊注解 | 继承 `ElasticsearchRepository`，提供 CRUD |
| `PostEsDao` | `esdao/PostEsDao.java` | 无特殊注解 | 继承 `ElasticsearchRepository` |
| `QuestionServiceImpl` | `service/impl/QuestionServiceImpl.java` | 注入 `ElasticsearchRestTemplate` + `QuestionEsDao` | `searchFromEs()`、`syncQuestionToEs()`、`cleanupAfterQuestionDelete()` |
| `PostServiceImpl` | `service/impl/PostServiceImpl.java` | 注入 `ElasticsearchRestTemplate` | `searchFromEs()`（无降级保护） |
| `FullSyncQuestionToEs` | `job/once/FullSyncQuestionToEs.java` | `@Component` **已注释** | 启动时全量同步题目到 ES |
| `FullSyncPostToEs` | `job/once/FullSyncPostToEs.java` | `@Component` **已注释** | 启动时全量同步帖子到 ES |
| `IncSyncQuestionToEs` | `job/cycle/IncSyncQuestionToEs.java` | `@Component` **已注释** | 每 60 秒增量同步题目 |
| `IncSyncPostToEs` | `job/cycle/IncSyncPostToEs.java` | `@Component` **已注释** | 每 60 秒增量同步帖子 |

### 3.3 YAML 配置

```yaml
spring:
  elasticsearch:
    uris: http://localhost:9200
    username: root
    password: 123456
```

### 3.4 运行时影响（ES 不可用时）

| 影响范围 | 表现 |
|---------|------|
| 应用启动 | 取决于 Spring Boot 版本对 ES 连接失败的处理，可能成功也可能失败 |
| `/question/search/page/vo` | 自动降级到 MySQL 查询，记录 warn 日志 |
| `/post/search/page/vo` | **报 500 错误**（无降级逻辑） |
| 题目增/改/删 | MySQL 正常，ES 同步静默失败，记录 warn |
| 同步 Job | 全部未启用，无影响 |

### 3.5 完整启用 ES 所需操作

| 步骤 | 文件 | 操作 |
|------|------|------|
| 1 | `QuestionEsDTO.java` 第 19 行 | 取消注释 `@Document(indexName = "question")` |
| 2 | `PostEsDTO.java` 第 25 行 | 取消注释 `@Document(indexName = "post")` |
| 3 | `FullSyncQuestionToEs.java` 第 24 行 | 取消注释 `@Component` |
| 4 | `FullSyncPostToEs.java` 第 21 行 | 取消注释 `@Component` |
| 5 | `IncSyncQuestionToEs.java` 第 24 行 | 取消注释 `@Component` |
| 6 | `IncSyncPostToEs.java` 第 24 行 | 取消注释 `@Component` |

## 4. HotKey（京东热 Key 探测）

### 4.1 当前状态：完全未启用

配置类和业务代码全部注释，虽然 pom 依赖存在且 YAML 有配置项，但运行时完全不激活。

### 4.2 涉及的类

| 类 | 文件位置 | 注解状态 | 功能 |
|----|---------|---------|------|
| `HotKeyConfig` | `config/HotKeyConfig.java` | `@Configuration` **已注释**，`@ConfigurationProperties` **已注释** | 初始化 HotKey 客户端（连接 Etcd） |
| `QuestionBankController` | `controller/QuestionBankController.java` | 使用代码**已注释**（第 154-188 行） | 题库详情页热 Key 缓存（Caffeine 本地缓存） |

### 4.3 pom 依赖

```xml
<dependency>
    <groupId>com.jd.platform.hotkey</groupId>
    <artifactId>hotkey-client</artifactId>
    <version>0.0.4-SNAPSHOT</version>
    <scope>system</scope>
    <systemPath>${project.basedir}/lib/hotkey-client-0.0.4-SNAPSHOT.jar</systemPath>
</dependency>
```

使用 `system` scope 引入本地 JAR（位于 `lib/` 目录下）。`spring-boot-maven-plugin` 配置了 `<includeSystemScope>true</includeSystemScope>` 确保打入 fat JAR。

### 4.4 YAML 配置

```yaml
hotkey:
  app-name: mianshiya
  caffeine-size: 10000
  push-period: 1000
  etcd-server: http://localhost:2379
```

配置存在但因 `@ConfigurationProperties` 被注释，不会被绑定到任何 Bean。

### 4.5 运行时影响

无任何影响。HotKey 完全不参与运行时行为。

### 4.6 完整启用 HotKey 所需操作

| 步骤 | 文件 | 操作 |
|------|------|------|
| 1 | 前置条件 | 部署 Etcd 服务 + HotKey Worker |
| 2 | `HotKeyConfig.java` 第 16-17 行 | 取消注释 `@Configuration` 和 `@ConfigurationProperties(prefix = "hotkey")` |
| 3 | `QuestionBankController.java` 第 154-165 行 | 取消注释热 Key 检查逻辑 |
| 4 | `QuestionBankController.java` 第 185-188 行 | 取消注释热 Key 写入逻辑 |
| 5 | `application.yml` | 确认 `hotkey.etcd-server` 指向正确的 Etcd 地址 |

## 5. Nacos（配置中心）

### 5.1 当前状态：半启用（有风险）

pom 依赖活跃，YAML 中 `bootstrap.enable: true`，意味着 `nacos-config-spring-boot-starter` 会在启动时尝试连接 Nacos。如果 Nacos 不可用，可能产生启动告警甚至失败（取决于 starter 版本的容错行为）。但实际的业务使用者 `NacosListener` 已被注释。

### 5.2 涉及的类

| 类 | 文件位置 | 注解状态 | 功能 |
|----|---------|---------|------|
| `NacosListener` | `blackfilter/NacosListener.java` | `@Component` **已注释** | 监听 Nacos 配置变更，动态更新 IP 黑名单 |
| `BlackIpFilter` | `blackfilter/BlackIpFilter.java` | `@WebFilter` **活跃** | 每个请求检查 IP 是否在黑名单中 |
| `BlackIpUtils` | `blackfilter/BlackIpUtils.java` | 工具类 | 管理布隆过滤器，维护 IP 黑名单 |

**关键说明**：`BlackIpFilter` 始终活跃（通过 `@WebFilter` + MainApplication 上的 `@ServletComponentScan`），但因 `NacosListener` 未启用，黑名单永远为空，`BlackIpFilter` 对每个请求都放行。

### 5.3 YAML 配置

```yaml
nacos:
  config:
    server-addr: 127.0.0.1:8848
    bootstrap:
      enable: true
    data-id: mianshiya
    group: DEFAULT_GROUP
    type: yaml
    auto-refresh: true
```

**注意**：`bootstrap.enable: true` 使 Nacos starter 在 Spring 容器初始化早期就尝试连接。

### 5.4 运行时影响（Nacos 不可用时）

| 影响范围 | 表现 |
|---------|------|
| 应用启动 | 可能出现连接告警或延迟（具体行为取决于 starter 版本容错） |
| IP 黑名单 | 无影响（`NacosListener` 未启用，黑名单为空，所有请求放行） |

### 5.5 完整启用 Nacos 所需操作

| 步骤 | 文件 | 操作 |
|------|------|------|
| 1 | 前置条件 | 部署 Nacos Server |
| 2 | `NacosListener.java` 第 26 行 | 取消注释 `@Component` |
| 3 | Nacos 控制台 | 创建 `mianshiya` 配置，格式 YAML，包含 `blackIpList` 字段 |
| 4 | `application.yml` | 确认 `nacos.config.server-addr` 指向正确的 Nacos 地址 |

### 5.6 如需完全关闭 Nacos

如果不使用 Nacos 且不想有启动探测行为，将 YAML 中 `bootstrap.enable` 改为 `false`：

```yaml
nacos:
  config:
    bootstrap:
      enable: false
```

## 6. Sentinel（流控与熔断）

### 6.1 当前状态：已启用

Sentinel 是纯客户端库，不依赖外部服务。规则在本地初始化和持久化。

### 6.2 涉及的类

| 类 | 文件位置 | 注解状态 | 功能 |
|----|---------|---------|------|
| `SentinelRulesManager` | `sentinel/SentinelRulesManager.java` | `@Component` **活跃** | `@PostConstruct` 初始化流控和熔断规则 |
| `SentinelConstant` | `sentinel/SentinelConstant.java` | 常量类 | 定义资源名 `listQuestionBankVOByPage`、`listQuestionVOByPage` |
| `QuestionBankController` | `controller/QuestionBankController.java` | `@SentinelResource` **活跃** | 题库分页接口的注解式流控 |
| `QuestionController` | `controller/QuestionController.java` | `SphU.entry()` **活跃** | 题目分页接口 (`/list/page/vo/sentinel`) 的编程式流控 |

### 6.3 已配置的规则

**流控规则**（`SentinelRulesManager.initFlowRules`）：
- 资源 `listQuestionVOByPage`：热点参数限流，每个 IP 每 60 秒最多 60 次请求

**熔断规则**（`SentinelRulesManager.initDegradeRules`）：
- 资源 `listQuestionVOByPage`（慢调用比例）：响应超 3 秒的比例 > 20% 时，熔断 60 秒
- 资源 `listQuestionVOByPage`（异常比例）：异常比例 > 10% 时，熔断 60 秒

规则持久化到本地文件 `sentinel/FlowRule.json` 和 `sentinel/DegradeRule.json`。

### 6.4 运行时影响

Sentinel 始终运行，无外部依赖。如需关闭，需要：
1. 注释 `SentinelRulesManager.java` 的 `@Component`
2. 移除 `QuestionBankController` 上的 `@SentinelResource` 注解
3. 移除 `QuestionController.listQuestionVOByPageSentinel()` 中的 `SphU.entry()` 调用
